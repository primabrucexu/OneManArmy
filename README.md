# OneManArmy

一个人提出软件需求，由一支可观察、可打断、可纠偏的 Codex Agent 团队完成交付。

> 当前状态：总体目标已确认，已完成可直接调用 Codex 的本地 Web Demo。

## 运行 Demo

需要 Node.js 18 或更高版本，并已在本机登录 Codex。

```powershell
npm install
npm run build
npm start
```

然后访问 `http://127.0.0.1:8765`，填写目标项目、任务和文件权限，即可启动一次真实 Codex 任务。当前 Demo 由仅监听本机的 Node.js 服务托管页面并调用 Codex，不需要远程后端。它只验证 Web UI 到 Codex 的完整调用链路，尚未实现下文所述的三阶段流程和审核角色。

运行自动测试：

```powershell
npm test
```

## 项目目标

OneManArmy 用于把软件项目中需要人工逐阶段推动的需求开发流程，转变为由审核角色把控的自动交付流程。

用户先与 Agent 充分讨论需求。F 文档经用户确认后，后续计划、编码、验证和修正由 Agent 自动推进；只有必须修改 F 文档或 Agent 无法自主判断时，流程才暂停并请求用户决策。

本项目基于 Codex，不建设通用模型平台，不设计模型供应商抽象、模型选择或模型路由能力。

## 第一阶段范围

- 面向软件需求开发，不处理研究、写作和日程管理等通用任务。
- 优先支持已有代码项目，以 AlphaPredator 一类具有现有代码、文档和项目约束的项目作为验证场景。
- 从零创建软件项目是后续改进方向，第一阶段不实现项目初始化能力。

## 工作流程

每个需求依次经过三个阶段。

### 1. 需求讨论

- 需求 Agent 与用户进行多轮讨论，明确目标、范围、非目标、业务口径和验收标准。
- 本阶段输出 F 文档。
- 审核 Agent 检查 F 文档是否完整、一致，是否包含未经确认的推断。
- F 文档必须由用户明确确认，确认后才允许进入自动执行流程。

### 2. 计划

- Agent 根据项目约束和已确认的 F 文档形成简要实现方案。
- 实现方案说明总体思路、影响范围、必要变更、任务拆分、验证方式和已知风险。
- 审核 Agent 检查方案是否符合项目约束和 F 文档。
- 审核通过的方案写入同一份 F 文档的 `How` 章节，然后自动进入编码阶段，无需用户再次确认。
- 如果方案需要改变需求目标、范围、行为或验收标准，流程必须返回需求讨论阶段，并由用户重新确认 F 文档。

### 3. 编码

- Agent 按 F 文档实现功能，并完成必要的测试、构建、文档同步和修正。
- 审核 Agent 检查代码差异、验证结果以及实现与 F 文档的一致性。
- 审核不通过时，成果退回修改；审核通过后进行最终整体验收并交付结果。
- 如果编码过程中需要改变 F 文档，流程必须返回需求讨论阶段。

## 审核与自动纠偏

- 每个关键阶段都必须接受独立审核，最终交付前还必须进行整体验收。
- 审核结果分为通过、退回修改和请求用户决策。
- 审核不通过时，Agent 根据具体意见自动修正并重新提交审核。
- 审核角色不得擅自改变 F 文档。
- 只有需要改变 F 文档、存在无法自主判断的产品选择，或自动修正无法解决问题时，才请求用户介入。

## 事实来源和优先级

整个流程遵循以下优先级：

1. 项目级约束。
2. 当前已确认的 F 文档中关于目标、范围、行为和验收标准的内容。
3. F 文档 `How` 章节中的当前实现方案。
4. 代码、测试及其他实现产物。

F 文档是单个需求的唯一标准。项目级约束具有更高优先级，但只能约束需求和实现边界，不能被 Agent 用来擅自增加业务需求。

如果 F 文档与项目约束冲突，Agent 不得绕过或静默选择，必须返回需求讨论阶段。如果客观技术事实表明当前方案不可行，Agent 应重新规划；确实需要改变需求时，再请求用户修订并重新确认 F 文档。

## F 文档维护原则

- F 文档模板复用 AlphaPredator 项目的 Feature 文档结构。
- F 文档中的需求内容定义要实现什么，`How` 章节保存计划阶段最新审核通过的简要实现方案。
- 不单独维护一份与 F 文档重复的实现计划。
- F 文档只保留当前最新且已通过审核的有效内容。
- 新方案通过审核前，原有 `How` 继续有效；通过后直接替换旧方案。
- 讨论草稿、被驳回的计划、旧方案和过期描述不进入正式 F 文档，也不另行归档。
- Git 可以自然保留文件历史，但 OneManArmy 不为旧方案建设额外的历史管理能力。

## 后续方向

- 支持从零定义和初始化新的软件项目。
- 在不改变三阶段流程和审核原则的前提下，完善过程观察、暂停、恢复和纠偏能力。
