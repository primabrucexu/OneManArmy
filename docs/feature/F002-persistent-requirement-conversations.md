# F002 历史需求对话与新建对话

**STATUS**：已实现并验证
**MileStone**：第一阶段

## What

### 目标

在项目的需求讨论界面中增加历史对话栏和“新建对话”能力，使同一项目可以并行维护多个相互独立的需求讨论。每个对话拥有自己的 Codex Thread、消息记录、需求文档草稿和待用户决策项，并在刷新页面或重启 OneManArmy 后继续保留。

### 页面结构

- 历史对话栏位于项目界面中聊天工作区的左侧、全局侧边栏的右侧。
- 项目上下文、三阶段进度和右侧审核栏保持现有结构。
- 历史对话栏是项目内部导航，不放入全局侧边栏。
- 对话栏保持紧凑，不提供展开、收起或调整宽度的按钮。

### 历史对话栏

- 顶部展示“需求对话”和“新建对话”按钮。
- 历史对话按最后更新时间倒序排列。
- 每条历史对话展示标题、最后更新时间和当前状态。
- 当前选中的对话具有明确的选中状态。
- 第一版状态包括：`讨论中`、`待用户决策`和`草稿已更新`。
- 没有历史对话时展示空状态，并引导用户新建对话。

### 新建对话

- 点击“新建对话”后，主工作区切换到一条新的空白需求讨论。
- 新对话拥有独立的 Codex `thread_id`、消息、需求文档、待决策项、版本和输入草稿。
- 新对话在用户发送第一条有效消息后写入历史记录，避免产生未使用的空对话。
- 对话标题由第一条用户消息确定，使用去除首尾空白后的前 24 个字符；超出部分以省略号显示。
- 第一版不提供手动修改标题。
- 当前已经是未发送消息的空白新对话时，再次点击“新建对话”不会重复创建空记录。

### 切换与恢复

- 点击历史项后，恢复该对话的消息、Codex `thread_id`、需求文档、待决策项、文档版本、输入草稿和讨论滚动位置。
- 每个历史对话相互隔离；一个对话的消息或需求文档不得写入另一个对话。
- 页面刷新后恢复刷新前选中的对话；没有可恢复选择时打开最近更新的对话。
- 项目没有历史对话时打开空白新对话。
- 需求 Agent 正在处理消息时，暂时禁止新建或切换对话，避免响应写入错误的对话。

### 本地持久化

- 历史对话必须在页面刷新和 OneManArmy 服务重启后继续存在。
- 持久化数据按规范化后的项目路径隔离。
- 会话数据保存在 OneManArmy 自己的本地数据目录中，不写入目标项目仓库。
- 持久化内容包括：对话标识、标题、Codex `thread_id`、消息、需求文档、待决策项、文档版本、输入草稿、滚动位置、创建时间和更新时间。
- 服务异常退出后，不将上一次未完成的请求继续显示为“处理中”；恢复为可继续发送的对话，并提示上一次请求未完成。
- 持久化失败时必须显示明确错误，不得把仅存在于内存中的状态伪装成已保存。

### 与 F001 的关系

- F001 继续定义单个需求讨论的聊天、需求文档和审核栏交互。
- F002 负责多个需求讨论的创建、切换、隔离和本地持久化。
- F002 生效后，替代 F001 中“页面刷新后会话丢失”和“不实现状态持久化”的限制。

### 非目标

- 不提供对话删除、重命名、搜索、归档或导出。
- 不提供云端同步或跨设备同步。
- 不提供多个项目的扫描、创建或删除。
- 不实现独立审核 Agent、计划阶段或编码阶段的业务流程。
- 不把完整历史对话一次性注入新的 Codex Thread。

## How

### 存储位置与格式

- 新增 `ConversationStore`，负责项目级会话数据的读取、校验和原子写入。
- 默认数据目录：Windows 使用 `%LOCALAPPDATA%\OneManArmy`；其他系统使用 `$XDG_STATE_HOME/OneManArmy`，未设置时使用用户目录下的 `.local/state/OneManArmy`。
- 支持通过 `ONEMANARMY_DATA_DIR` 覆盖数据目录，便于测试和本地部署。
- 项目路径先解析为规范化绝对路径；Windows 下以不区分大小写的路径计算 SHA-256 项目标识。
- 每个项目使用独立的 `projects/<project-hash>/state.json`，不在目标项目目录中创建文件。
- `state.json` 保存 schema 版本、规范化项目路径、当前对话 ID 和完整对话集合。
- 写入使用同目录临时文件加原子替换，避免服务异常退出留下半个 JSON 文件。
- 文件不存在视为没有历史记录；文件无法解析或 schema 不合法时返回明确错误，不静默覆盖。

### 持久化模型

每个对话保存：

- `id`：服务端生成的 UUID。
- `title`：第一条有效用户消息去除首尾空白后的前 24 个字符，超出时追加省略号。
- `threadId`：Codex SDK 返回的 Thread ID；首轮完成前允许为空。
- `messages`：用户、需求 Agent 和系统状态消息，包含稳定 ID、角色、正文和时间。
- `document`：当前需求文档标题、目标、范围、非目标、主要行为和验收标准。
- `pendingDecisions`：当前待用户决策项。
- `documentVersion`：每次 Agent 成功返回后递增。
- `inputDraft` 与 `scrollTop`：对话切换和刷新时恢复 UI 状态。
- `requestStatus`：`idle`、`running`、`interrupted`。
- `createdAt` 与 `updatedAt`。

历史栏展示状态由持久化内容确定：存在待决策项时为“待用户决策”；否则已有文档版本时为“草稿已更新”；其余为“讨论中”。

### 服务端接口

1. `GET /api/discussions?project_path=...`
   - 返回项目的历史对话摘要列表和当前对话 ID。
   - 摘要包含 ID、标题、状态、创建时间和更新时间，不返回完整消息正文。
2. `GET /api/discussions/:conversation_id?project_path=...`
   - 返回单个对话的完整持久化状态。
3. `POST /api/discussions/messages`
   - 接收项目路径、用户消息和可选 `conversation_id`。
   - 不再接受客户端提供的 `thread_id`；服务端从会话记录读取，避免对话与 Thread 被错误组合。
   - 没有 `conversation_id` 时创建新对话并生成标题；有 ID 时续接对应 Codex Thread。
   - 调用 Codex 前先持久化用户消息和 `running` 状态，成功后原子保存 Agent 回复、需求文档、待决策项和 Thread ID。
   - 同一对话已有请求运行时返回 `409`，避免并发写入和串话。
4. `PATCH /api/discussions/:conversation_id`
   - 只允许更新输入草稿、滚动位置和是否设为当前对话。
   - 不提供标题、消息、Thread ID 或文档正文的任意修改能力。

服务启动或读取数据时，如果发现 `requestStatus=running`，将其恢复为 `interrupted`，并向界面返回“上一次请求未完成，可继续发送”的真实状态。

### 前端状态与交互

1. 在现有项目内容网格中新增固定宽度的项目内历史栏，形成“历史对话 / 当前工作区 / 审核栏”三栏结构。
2. 进入项目页时先读取历史摘要；恢复服务端记录的当前对话，没有历史时显示空白新对话。
3. 点击历史项前保存当前对话的输入草稿和滚动位置，再读取并渲染目标对话。
4. 点击“新建对话”时保存当前 UI 状态，然后切换到未持久化的空白对话；发送第一条消息后由服务端返回正式 ID，并加入历史列表顶部。
5. 输入草稿使用短延迟防抖保存；滚动位置在停止滚动和切换对话时保存。
6. Agent 响应期间禁用“新建对话”和全部历史项；响应成功或失败后恢复。
7. 发送成功后更新当前对话、历史摘要顺序、标题、状态和更新时间，不重建其他对话状态。
8. 刷新页面后重新从服务端读取，不依赖浏览器 `localStorage` 作为事实来源。
9. 历史栏在窄桌面布局中保持项目内导航语义，不合并到全局侧边栏。

### 错误处理

- 历史列表读取失败时，项目页显示持久化错误并禁止新建或发送，避免产生无法保存的假会话。
- 单个对话读取失败时保留历史列表，并在主工作区显示可重试错误。
- 消息调用失败时保留已持久化的用户消息，将对话标记为中断并恢复输入能力。
- 草稿或滚动位置保存失败时显示非阻断警告；不能显示“已保存”。

### 验证计划

1. `ConversationStore` 测试：首次读取、原子写入、服务重建后恢复、项目隔离、损坏文件和 `running → interrupted` 恢复。
2. API 测试：历史摘要、详情读取、首轮创建、续接 Thread、当前对话、草稿/滚动更新、未知 ID 和并发 `409`。
3. 回归测试：原有项目配置、通用 `/api/runs`、需求 Agent 结构化输出和静态资源服务继续通过。
4. 浏览器验证：新建两个对话、切换隔离、标题/排序/状态更新、草稿恢复、刷新恢复、错误状态和 Agent 运行期间禁用切换。
5. 运行 `npm test` 与 `npm run build`；浏览器控制台不得出现错误。

## Acceptance Criteria

1. 项目需求界面的聊天工作区左侧展示历史对话栏和“新建对话”按钮。
2. 用户可以创建多个需求对话，每个对话拥有独立的消息、Codex Thread、需求文档和待决策项。
3. 新对话发送第一条消息后出现在历史列表中，并使用第一条消息生成标题。
4. 历史对话按最后更新时间倒序排列，当前对话具有明确选中状态。
5. 切换历史对话后，可以恢复对应的消息、需求文档、待决策项、输入草稿和滚动位置。
6. 一个对话的内容不会出现在另一个对话中。
7. 刷新页面或重启 OneManArmy 后，历史对话仍然存在，并恢复上次选择或最近更新的对话。
8. 会话数据保存在 OneManArmy 本地数据目录，不修改目标项目仓库。
9. 需求 Agent 正在响应时，用户不能新建或切换对话。
10. 持久化失败或上次请求异常中断时，界面提供真实、明确的状态反馈。
11. 页面不展示尚未实现的删除、重命名、搜索、归档、导出或云同步能力。
