# 讨论焦点提醒与重点标记

## 目标

保持需求讨论围绕当前问题展开，并让用户快速识别需要判断和确认的内容。焦点包括核心问题、本次讨论范围（讨论到什么程度）和当前待定事项，保存在现有 `requirement-draft.md` 中；讨论日志保存提醒内容及目标变化，不再维护另一份焦点状态。

项目总目标与本次焦点分别表达。例如项目目标是完善 OMA，本次焦点可以只是确定需求讨论的提醒方式。

## 提醒与话题变化

- 首次明确目标，在中断、任务交接或上下文丢失后恢复讨论，准备深入可能偏离目标的新方向，以及展示最终交付清单前，简短提醒当前焦点。连续讨论中的常规读取，以及路由返回 `resume` 本身，不触发节点提醒。
- 持续讨论默认每 5 轮用户与助手的交流提醒一次。工具调用不计轮次；节点提醒后重新计数，同一回复触发多个条件时只提醒一次。
- 提醒用两三句话说明当前目标、已形成的结论和接下来要决定的问题。没有新的决定时继续讨论，不因提醒额外索取确认。
- 为决定 A 而探索 B 时，说明两者的关系，完成必要探索后回到 A。B 形成独立目标或交付范围时提示可能偏移，不因顺便提到 B 就将它纳入交付清单。
- 用户明确要求改为 B 时，更新焦点并简述 A 暂缓或结束，无需重复确认同一决定；只有意图不明确且会实质改变范围时才询问。

## 重点输出

阶段总结、方案输出和最终清单用少量加粗及稳定编号突出：

- **已确认：** 用户明确决定的内容。
- **待确认／建议：** 尚未决定的取舍，推荐方案不能写成既定结论。
- **本轮变化：** 相比上次新增、删除或改变的实质内容。

重点围绕范围、用户可见行为、关键取舍和验收条件；没有相关内容时无需填满所有类别。摘要帮助阅读，最终确认仍对应完整交付清单。回答部分重点问题不等于最终确认全部执行。

## 计数与恢复

`discussion-state.json` 只增加 `lastFocusReminderTurn`，新讨论初始为 `0`。`record` 每保存一次完整的用户与助手交流，沿用现有 `turnCount` 增加一轮；输入可选布尔值 `focusReminderShown`，默认 `false`。仅当本轮回复实际包含焦点提醒时传入 `true`，脚本把上次提醒轮次更新为本轮，并在讨论日志中保存该标记。

`show` 返回 `focusReminder: { intervalTurns: 5, due: boolean }`。`due` 针对即将回复的下一轮：讨论尚未确认，且 `turnCount + 1 - lastFocusReminderTurn >= 5` 时为 `true`。未展示提醒时，到期状态持续保留。首次明确目标等节点由 Skill 判断，可以在周期到期前提醒并重新计数。

读取或恢复讨论不会增加轮次，也不会重置计数。旧状态缺少 `lastFocusReminderTurn` 时按 `0` 计算；确认完成后 `due` 为 `false`。焦点从草稿恢复，实际提醒从日志追溯。

## 验证范围

程序测试覆盖周期到期、节点提前提醒后重新计数、未提醒时保持到期、恢复后的计数延续、非讨论工具调用不计轮次，以及确认后不再提示周期提醒。

语义与输出格式由 Discuss 执行，需要通过对话案例检查：

| 场景 | 应观察到的行为 |
| --- | --- |
| 为决定 A 探索必要前提 B | 解释关联，完成必要探索后回到 A |
| B 开始形成独立功能 | 提醒范围变化，不自动纳入交付 |
| 用户明确改为 B | 更新焦点，说明 A 的状态，不重复确认 |
| 恢复长讨论 | 读取已有焦点和计数，给出简短提醒并记录 |
| 输出总结与最终清单 | 区分已确认、建议和变化，保留完整确认范围 |

计数测试不能证明模型必然正确识别偏题，也不代表真实 OMA 全流程已经验收。
